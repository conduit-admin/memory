# memory

«Лучезарность» — сайт личного хранилища знаний: листки по физике, серии
по математике, конспекты в PDF. До 2026-10-07 назывался «Хранилище»; имя
теперь по каналу владельца, знак тот же, что у канала. Иконки домашнего
экрана — `assets/icons/`, нарисованы из координат `manim/kanal/logo.svg`.
Читается с телефона по ссылке, ставить ничего не надо.

## Как устроено

Сборки нет. GitHub Pages раздаёт репозиторий как есть, страница читает `data/`
прямо в браузере. Правка = коммит, никаких Actions и ожидания пайплайна.

```
index.html                страница целиком
assets/style.css          оформление
assets/app.js             читалка: маршруты, разбор markdown, связи
assets/fonts/             Golos Text, кириллица и латиница отдельными файлами
data/config.json          заголовок и метка сборки
data/index.json           что вообще есть в базе; собирается скриптом
data/notes/               копия человеческой зоны knowledge
tools/publish.py          то, что всё это собирает
```

Каталог браузеру не перечислить — поэтому список заметок заранее пишется
в `data/index.json`: путь, заголовок, поля фронтматтера и вики-ссылки. Из ссылок
на стороне браузера строятся обратные: «кто ссылается на эту заметку».

## Откуда берётся содержимое

Из репозитория `knowledge`, поток строго в одну сторону. **Здесь ничего не пишется
руками** — `data/notes/` перестраивается целиком при каждом запуске.

## Когда сайт обновляется

Сам по себе — никогда. Сборки нет, значит, и пересобирать нечему: сайт меняется
ровно в тот момент, когда сюда приезжает коммит. Изменение в `knowledge` само
по себе на сайт не попадает.

Поэтому обновление сведено к одной команде:

```
python tools/deploy.py
```

Она пересобирает витрину, коммитит и пушит. Раньше это были три шага, и сайт
отставал ровно настолько, насколько легко забыть второй и третий.

Берётся **рабочее дерево** `knowledge`, а не последний коммит: обновить сайт
хочется сразу, не дожидаясь осмысленного коммита. Обратная сторона — публичный
сайт может опережать приватную историю. Сообщение коммита витрины ссылается
на состояние источника, поэтому видно, чему соответствует сборка.

Отдельно только сборку копии, без коммита:

```
python tools/publish.py [путь-до-knowledge]
```

Что попадает наружу, задано белым списком в начале скрипта. Именно белым: при
чёрном новая папка в knowledge уехала бы в публичный доступ молча, а забытая
строка в белом списке всего лишь оставит её неопубликованной.

Служебная зона `knowledge/.claude/`, черновики и шаблоны не публикуются вовсе —
их нет в списке.

## Два репозитория и почему именно так

| | `knowledge` | `memory` |
|---|---|---|
| Видимость | **приватный** | **публичный** |
| Что внутри | заметки, работы, служебная зона `.claude/` | код сайта и копия человеческой зоны |
| Кто пишет | Claude Code по ходу разбора | `tools/publish.py`, одной командой |
| Зачем | источник правды | то, что читают с телефона |

Разделение не по красоте, а по трём причинам сразу.

**История git публикуется целиком.** Удалить файл новым коммитом — не значит
убрать его из репозитория: он остаётся в истории и доступен всем. У `knowledge`
история длинная и с переездами, чистить её задним числом дорого и ненадёжно.
У `memory` история начинается с чистого листа и наполняется только тем, что
прошло белый список.

**Служебная зона не должна выходить наружу вообще.** В `.claude/` лежат
договорённости, разбор граблей конкретной машины и заметки о доступах. Ничего
секретного там нет, но и публиковать это незачем. Пока она в приватном
репозитории, вопрос закрыт устройством, а не аккуратностью.

**Изъятия должны быть в одном месте.** `tex/reference/veroyatnost.pdf` —
конспект в соавторстве, и публиковать чужую часть без разговора нельзя. Он
изъят в `EXCLUDE`, и этого достаточно: наружу физически уезжает только то, что
скрипт скопировал.

Сами сайты — `conduit-26` и `conduit-city-26` — остаются своими репозиториями.
Сюда попадают только карточки с описанием и ссылкой.

**Почта в коммитах.** В публичном репозитории адрес автора виден и собирается
автоматически. Лечится до первого push:

```
git config user.email "<номер>+<логин>@users.noreply.github.com"
```

Адрес берётся в GitHub → Settings → Emails. Прошлые коммиты это не исправит,
но здесь их всего два и они локальные.

## Что умеет

- заметки: markdown, формулы, `[[вики-ссылки]]`;
- **обратные ссылки** — ради них соглашение о вики-ссылках и заведено;
- PDF открывает браузер сам, своей читалкой, **с первого нажатия**: строка,
  карточка и вики-ссылка ведут прямо в файл, в новой вкладке. Сайт и ролик
  с полем `video` — так же. Страницы «о файле» нет с 2026-10-07; старый
  адрес `#/f/…` перенаправляет в PDF;
- **поиск по названиям** — поле в шапке, по всем вкладкам сразу, без
  индекса: перебор пары сотен названий в браузере ничего не стоит;
- **миниатюры обложек** у документов A5: `tools/publish.py` рисует первую
  страницу через `pdftoppm` в `data/thumbs/`, только когда PDF новее
  картинки. Нет `pdftoppm` — нет миниатюр, остальное работает;
- тёмная тема, ставится на домашний экран как приложение.

Графа и правки из браузера нет намеренно: ни то ни другое не нужно,
а поддерживать пришлось бы всё. Правка не нужна и потом — всё пишется
через Claude Code и приезжает сюда коммитом.

Пять вкладок:

```
Проекты      Свежее — пять последних изменённых файлов из всех разделов
             Анимации — название, стадия производства; с `video` — ▶
             Сайты — строка ведёт на сайт, под ней «Редактор», если есть
             Репетиторство — PDF листков из tutoring/listki/
             Статьи — остальное из tex/documents/, кроме ml/
             Стили — все style.md одним блоком

Физика       План обучения — заметки physics/ с type: plan
             Серии, Разборы, Эксперимент, Теория — PDF листков
             из подпапок physics/listki/; новая подпапка — новый блок

Математика   Серии матцентра, свежие сверху: листок по нажатию, даты,
             «решено N из M» и задачи кружками; ниже гробарий. Всё из двух
             таблиц math/serii.md, которые пишет синхронизация с кондуитом

             Конспекты — все заметки из ml/, по названию

             в app.js), порядок по poryadok, кнопка «Копировать» — текст
             промпта лежит в индексе, его кладёт publish.py (role_prompt)
```

Вкладка «Зачёт» снята 2026-10-01: ею не пользовались. «Математика» снималась
тогда же, а 2026-10-02 вернулась в другом виде: вместо разборов и приёмов
(они ушли в math/arhiv/ и на сайт не идут) — серии и отметки о решённом.
Блок «Зачёт» в «Проектах» снят 2026-10-07: зачёт прошёл, его документы —
в архиве на сайте кружка, и выкладка их больше не отдаёт (`EXCLUDE_DIRS`).

Имя файла в knowledge стоит на каждой карточке: по нему заметку находят
в репозитории, не гадая, как она там называется.

готов, выложен. Поле `stadiya` во фронтматтере карточки ролика.

## Оформление

Палитра, подложка и стекло взяты из «Кондуита» без переизобретения: это один
дом-стиль на два сайта. Светлая и тёмная темы — два отдельных набора шагов,
а не автоматическая инверсия.

## Ссылка, открывающая сайт в Chrome

```
https://conduit-admin.github.io/memory/open.html
```

Ссылка, отправленная в мессенджере, открывается во встроенном браузере приложения:
там нет ни установки на домашний экран, ни нормального кэша. `open.html` уводит
оттуда в Chrome — на Android адресом `intent://` с указанием пакета браузера,
на iPhone через `googlechromes://`. Не установлен или не отозвался — остаётся
обычный сайт; из самого Chrome прыжка не происходит.

Адрес сайта в файле не записан, а берётся из того, по которому открыта сама
страница, так что переезд репозитория её не сломает. Копия такого же файла лежит
в `conduit-city`.

## Внешние зависимости

Одна: `marked` разбирает markdown, `KaTeX` верстает формулы — оба с cdnjs,
версии закреплены. Всё остальное своё, включая шрифты. Когда дойдут руки, обе
библиотеки кладутся в `assets/`, и внешних запросов не остаётся вовсе.

## Кэш

Страница носит метку сборки в `<meta name="build">`. `config.json` берётся мимо
кэша, и если метка в нём новее — страница перезагружается по адресу с новой
меткой. Данные и заметки запрашиваются уже с меткой в адресе: промах кэша
обеспечивается самим адресом, а не просьбой к браузеру — просьбу он вправе
истолковать по-своему, что при первой же проверке и случилось.
