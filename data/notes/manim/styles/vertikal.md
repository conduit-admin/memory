# Вертикаль

Стиль анимаций: вертикальный кадр 9:16, чёрный фон, палитра своя на каждый
ролик, темп задаётся константой.

## Формат — вертикаль 9:16

Шапка у всех роликов одинаковая:

```python
from manim import *

config.pixel_height = 1920
config.pixel_width = 1080
config.frame_height = 16.0
config.frame_width = 9.0
```

Кадр 9 единиц в ширину, 16 в высоту. Это главное ограничение композиции:
**по горизонтали места нет, по вертикали его много.** Отсюда типовая раскладка —
формула сверху, геометрия снизу через `shift_v = DOWN * 3`, объект уменьшен
до `scale_f = 0.6`.

Формулы почти всегда шире кадра, поэтому подрезаются явно:

```python
if formula.width > config.frame_width - 0.5:
    formula.scale_to_fit_width(config.frame_width - 0.5)
```

Запас по краям 0.4–0.5. В `planar.py` кадр 10.8×19.2 — то же соотношение,
просто другой масштаб мировых единиц. Выбирается один раз на ролик.

**Безопасная зона — измерена 19.09.2026** закрытой выкладкой немого
рендера Разрезания на квадраты, по скриншоту с телефона владельца.
Телефон 19,5:9 показывает кадр с лёгкой обрезкой по бокам (край
$x = \pm 4{,}35$ не виден), около 106 px на единицу; калибровка —
по ширине верхней формулы и по тому, что формула на $y = -5{,}3$
оказалась под именем канала. Точность ±0,2 единицы. Перекрыто
не «низ и правый край», а три разных куска:

| что | высота 16 | высота 19,2 |
|---|---|---|
| низ: заголовок, имя канала, дата — 20 % | всё ниже $y = -4{,}9$; держать содержимое выше $-4{,}5$ | ниже $-5{,}9$; держать выше $-5{,}4$ |
| правый столбец кнопок — 15 % ширины, нижние 55 % высоты | $x > 3{,}0$ при $y < -0{,}9$; выше вся ширина свободна | $x > 3{,}6$ при $y < -1{,}1$ |
| верх: стрелка и поиск по углам — 6 % | $y > 7{,}0$ при $x < -3{,}5$ или $x > 2{,}5$; середина верха свободна до $7{,}9$ | $y > 8{,}4$ по углам; середина до $9{,}5$ |

Отсюда раскладка: формулы наверху могут идти во всю ширину; чертёж
и формулы внизу — не ниже $-4{,}5$ и не правее $3{,}0$. Разрезание
на квадраты под это не помещается: $s = a/m = b/n$ на $-4{,}3\ldots-5{,}3$,
минус-клемма и нижняя шина цепи Кирхгофа на $-5{,}0\ldots-5{,}6$, правый
резистор цепи на $x = 3{,}0\ldots3{,}7$ в нижней половине, наезд на угол
в 0:36 до $-5{,}1$ и $3{,}8$; правый край листа на $3{,}5$ — под иконками.
Лечение — композиция меньше на десять процентов и выше на полединицы.

Типовая раскладка «геометрия снизу через `DOWN * 3`» с `scale_f = 0.6`
упирается в границу $-4{,}5$ — нижний край объекта проверять по числу,
не на глаз. Формула, подрезанная до `frame_width - 0.5`, доходит
до $x = 4{,}25$ — наверху это допустимо, внизу (при $y < -0{,}9$) нет.

## Файл = ролик, класс = сцена

Один `.py` на ролик, внутри несколько `Scene`; склейка встык — последний
шаг рендера, а не монтажа: ролик уходит в озвучку одним файлом. Имена
по смыслу: `InertiaShort`, `RodInertiaShort`, `PlatePromise`,
`TiltedContradiction`. Без нумерации — порядок держится раскадровкой
в шапке файла.

Геометрия, общая для нескольких сцен, живёт на уровне модуля, а не внутри `construct`.
Причина: сцена 2 должна начинаться ровно тем кадром, которым кончилась сцена 1.
Стыки проверяются до склейки сравнением последнего кадра с первым —
попиксельно, как у `squared_rectangle.py`.

## Раскадровка пишется до кода

Первой строкой — обещание словами зрителя; дальше биты с секундами
и прикидкой слов (два слова в секунду, см. [[konvencii]]); потом сцены
с шагами. Стрелки между шагами, глаголы в настоящем времени. Сначала этот
блок, потом код.

```python
# ============================================================================
# ОБЕЩАНИЕ: какие прямоугольники режутся на квадраты — те, у которых
#   отношение сторон дробь.
#
# 0:00-0:05  обещание  — лист уже разрезан, квадраты расходятся      ~12 сл.
# 0:05-0:16  установка — лист плывёт к 3:4, сетка, общая мера        ~28 сл.
# 0:16-0:51  поворот   — лемма, гель и ток, R = 1 Ом, цепь Кирхгофа  ~90 сл.
# 0:51-0:57  результат — b/a ∈ Q, разрезы зарастают — первый кадр     ~10 сл.
#
# СЦЕНА 1 (PlatePromise) — лист разрезан с первого кадра -> квадраты
#   расходятся -> смыкаются -> разрезы зарастают.
# СЦЕНА 2 (PlateMorph) — начинается тем же цельным листом, габариты плывут.
# ============================================================================
```

**Первый кадр — установка в сборе, и действие с первого кадра.** Всё,
что есть в кадре на нулевой секунде, собирается до первого `play`,
а первый `play` начинается без `wait` перед ним: сосуд стоит и сразу
раскручивается, лист лежит разрезанным и квадраты сразу расходятся.
Точки на чёрном и `Write(title)` в первые полторы секунды — это старые
ролики, так больше не делается.

## Палитра — своя на каждый ролик

Единой палитры проекта нет и не нужно. У каждого ролика свой набор именованных
констант в шапке, с комментарием о **роли** цвета, а не об оттенке:

```python
LIQUID_BODY = "#7C39EA"   # тело жидкости (сквозь стекло станет серее)
LIQUID_TOP  = "#9C6BF5"   # видимая напрямую поверхность — светлая
GLASS_COLOR = "#3a3a45"   # полупрозрачное серое стекло
F_CF_COLOR  = "#F4A93A"   # центробежная сила (оранжевая, вправо)
MG_COLOR    = "#35C9C0"   # сила тяжести (бирюзовая, вниз)
```

Годятся оба источника: **свои `#hex`** — когда нужен конкретный тон (металл,
жидкость, стекло); **встроенные имена** (`TEAL`, `PINK`, `PURPLE`, `ORANGE`,
`GOLD`, `BLUE`) — когда их хватает, как в `squared_rectangle.py`. Принцип
«каждой величине свой цвет» держится в обоих случаях.

Что держится во всех роликах:

- **Фон чистый чёрный** `#000000`, не «почти чёрный».
- **Каждая физическая величина — свой цвет**, и он не меняется всю сцену.
- **`#87CEFA`** — светло-голубой для рёбер графа и стержней. Единственный цвет,
  кочующий между роликами.
- Оттенки одного объекта — тремя константами (тон / светлее / темнее),
  а не подбором на месте.

## Текст

Математика — `MathTex`, подписи и имена — `Text`.

Кириллица в `Text` работает **без указания шрифта**: `Text("Индукция", font_size=72)`.

Но текст в кадре — решение **уровня ролика**. Серия `squared_rectangle` (@MathDzeta)
намеренно **без единого русского слова в кадре**: на экране только формулы (`MathTex`),
всё словесное — в озвучке диктора. Тогда `Text` не нужен вовсе.

Фиксированного кегля нет: крупная надпись 64–72, формула вывода 58,
подпись-имя `.scale(0.65)`, акцентная формула `.scale(1.2..1.5)`.

## Формулы собираются из кусков

Формула почти никогда не единая строка — её режут на токены, чтобы переход
двигал термы адресно, а не перерисовывал всё:

```python
eq_0 = MathTex("J_{", "S", "}", "=", r"\sum_{i}", "m_i", "|", "S", "A_i", "|", "^2")
eq_1 = MathTex("J_{", "S", "}", "=", r"\sum_{i}", "m_i", r"\vec{", "S", "A_i", "}", "^2")
self.play(TransformMatchingTex(eq_0, eq_1, run_time=1.0))
```

Либо `substrings_to_isolate=["M", "L", "dx"]`, когда достаточно выделить символы
внутри готового выражения.

Дробь, части которой должны разъезжаться, собирается вручную из `Line` + числитель +
знаменатель, а не через `\frac`: тогда куски двигаются адресно и ничего не «подтягивается».

## Трансформы текста — только там, где без них нельзя

Переход между формулами — самое частое место, где ролик дешевеет. Трансформ
ставится там, где он показывает **действие** над формулой, и нигде больше;
он должен быть уместным и умеренным. Правило от 2026-09-17, выведено
на разрезании на квадраты, где формулы переписывались целиком на каждом шаге.

- **Дописать** к формуле хвост — значит дописать: `Write` новых токенов справа,
  левая часть не двигается и не перерисовывается. Если строка после этого
  должна стоять по центру, она с самого начала ставится с учётом хвоста.
- **Сократить** — значит убрать: сокращаемые токены гаснут, соседи сдвигаются
  на освободившееся место (`.animate.move_to`). Строка не переписывается.
- **Схлопнуть** равенство `R = ρ/h = 1 Ω` до `R = 1 Ω` — то, что остаётся,
  едет; то, что уходит, гаснет. Ничего не пересобирается заново.
- **Подстановка** (`l → c`, `S → c·h`) — единственный случай, где токен
  действительно становится другим, и `ReplacementTransform` уместен. Один раз,
  а не по каждому шагу.
- **Акцент перед действием не нужен.** `Indicate` на сокращаемых буквах
  за секунду до того, как они исчезнут, — лишнее движение: само исчезновение
  и есть акцент.
- **Движущийся текст не проходит сквозь другие объекты** и не ложится на них.
  Маршрут каждого токена проверяется по кадру, как подпись на чертеже.

Проверка простая: если в переходе двигается больше токенов, чем изменилось
по смыслу, — переход сделан неправильно.

## Темп

Рабочие величины: `run_time` 0.6 / 0.8 / 1.0 / 1.5 покрывают почти всё,
0.4–0.5 для мелких сдвигов, 1.8–3.0 для финальных уходов.
`self.wait` 0.2–0.5 между шагами. После содержательной формулы диктору
нужны секунда-полторы — но не стоп-кадром: в это время что-то живёт
(дорисовка детали, медленный ход камеры, подсветка терма). Пауз длиннее
двух секунд не бывает вовсе, застывшего кадра дольше четырёх — тем более:
это проверяет `kanal/statika.py`.

Секунды сцене назначаются с оглядкой на слова: два слова в секунду,
в десятисекундный кусок помещается двадцать. Итоговые длительности
выставляет подгонка после озвучки — отдельным проходом, по местам,
где голос не помещается; поэтому константы темпа должны быть такими,
чтобы этот проход был правкой чисел, а не переписыванием сцены.

Два подхода, оба живут в проекте:

- **Константа скорости** (`inertia.py`) — в начале `construct` коэффициент, все
  длительности делением на него. Весь кусок ускоряется **одним числом**; удобно,
  когда правишь темп сцены равномерно.

  ```python
  SPEED_START = 2.0
  self.play(FadeIn(dots, lag_ratio=0.1), run_time=1.5 / SPEED_START)
  self.wait(0.5 / SPEED_START)
  ```

- **Явные `run_time`** (`squared_rectangle.py`) — у каждого `play` своё число.
  Гибко, когда фазы ускоряются **по-разному** («заживление ещё быстрее остального»),
  но равномерный «ускорь всю сцену» превращается в правку десятка чисел. Компромисс —
  константа **на фазу**, а не одна на ролик.

## Слои задаются явно

`z_index` расставлен почти на каждом значимом объекте — в коде полторы сотни мест.
Подписи и точки поверх заливок, аннотации поверх геометрии.
**Если объект пропал под заливкой — причина почти всегда здесь.**

## Апдейтеры: две пойманные грабли

Захват переменных в лямбде — только через дефолтные аргументы, иначе поздняя привязка
соберёт всё на последнюю итерацию цикла:

```python
label.add_updater(lambda m, d=dot, dir_vec=d_out: m.next_to(d.get_center(), dir_vec, buff=0.25))
```

Геометрию, зависящую от трекера, строить через `always_redraw` от **абсолютного**
значения, а не поворачивать объект инкрементами. В `rotating_liquid.py` база крутилась
через `m.rotate(w * dt)` прямо в объекте и на границе `play` → `wait` откатывалась
на ~146°, хотя трекер оставался цел. Пересбор каждый кадр к откату иммунен.

`ImageMobject.become()` требует одинаковой формы массива. Если габариты куска меняются
покадрово — разрешение массива фиксируется, а мировой размер задаётся `stretch_to_fit_*`.

Объекты, которые рождаются и умирают покадрово — искры, частицы, следы, — держать
**пулом**, созданным один раз, а не создавать заново в апдейтере. Рендерер берёт
список объектов в начале каждого `play`; штрих, выброшенный из группы, из этого
списка не уходит и рисуется там, где его застало начало `play`. Симптом: частицы
зависают в воздухе на весь следующий `play`. Пойман 2026-09-18 на искрах лазера
в `squared_rectangle.py`: искра берёт свободный штрих из пула, двигает его
через `put_start_and_end_on`, умирая — гасит `set_stroke(opacity=0)`.

`become` и **пустая группа** — две грабли с одного места, обе пойманы
2026-09-18. Если группа под `always_redraw` в первом кадре пуста (разрезы
до старта фронта), `become` подкладывает в неё точки-заглушки с `z_index = 0`,
и `set_z_index` на группе, которую вернула функция, до них не доходит —
линии оказываются под кусками. А `become` **в** пустую группу оставляет
старым линиям по одной точке в центре со стилем самой группы: белая точка
шириной 4 посреди кадра. Лечится обёрткой вместо `always_redraw`: слой
выставляется заново при каждой перерисовке, а пустой результат не
`become`'ится — старые линии гасятся. В `squared_rectangle.py` это
`always_redraw_z`.

Ещё два правила про `play`, стоившие по рендеру каждое. **Kwargs `play`
перекрывают kwargs анимаций**: `self.play(a, b, run_time=1.6)` ставит 1.6
и той анимации, у которой был свой `run_time`; разные длительности в одном
`play` — только через `.animate(run_time=...)` и явные kwargs у каждой,
без kwargs у `play`. **Камера двигается анимацией, не апдейтером**: всё,
что в этом `play` не анимируется, рендерер печёт в статичную картинку,
и кадр, сдвинутый апдейтером, лист за собой не потянет. Один плавный ход
камеры через несколько `play` — `UpdateFromAlphaFunc` на кадре в каждом
из них по общему графику (`camera_leg`).

## Что чем анимируется

По убыванию частоты: `FadeOut`, `Write`, `Create`, `ReplacementTransform`, `FadeIn`,
`LaggedStart`, `Flash`, `TransformMatchingTex`, `GrowArrow`.

- Появление группы — `FadeIn(group, lag_ratio=0.1)`.
- Акцент на точке — `Flash(dot, color=YELLOW, flash_radius=0.5, line_length=0.2)`.
- Замена формулы — `ReplacementTransform`, не `Transform`.
- `rate_func`: по умолчанию `smooth`, `linear` для равномерного вращения,
  `ease_in_out_sine` для разгона-торможения, `rush_into` для улёта в точку.

`Axes()` не использован ни разу — оси строятся вручную из `Line` и `Arrow`
с подписями `MathTex(..., color=YELLOW)`.

У каждого события в кадре есть момент начала — под него в монтаже ляжет
звук (лазер, ток, появление формулы). Размытое «что-то плавно
проступило» озвучить нечем; событие с началом — есть чем.

## Концовка

**Титров нет.** В первых четырёх роликах последней шла сцена с надписью
`credits: @MathDzeta` и паузой на три-четыре секунды; от неё отказались —
она уводит ровно там, где считается досмотр. Имя канала и логотип
не придуманы и отложены; когда появятся — из кода, мелко, в верхней
трети, монтаж поверх картинки ничего не накладывает. Правило целиком —
в [[konvencii]].

Сцена доводится до кадра результата, и он держится полторы секунды:

```python
annotations = [m for m in self.mobjects if m is not cross]
self.play(*[FadeOut(m) for m in annotations], run_time=0.9)
self.wait(1.5)
```

**Последний кадр совпадает с первым.** Ролик зациклен, поэтому увод
сцены идёт не в пустоту, а обратно к установке в исходном состоянии:
разрезы зарастают, сосуд останавливается, граф складывается в карту.
Практическое следствие для кода — объекты первого кадра живут отдельной
группой на уровне модуля; к финалу всё накопленное по ходу вывода
гаснет, а группа анимацией приводится в исходное положение. Результат
перед этим держится свои полторы секунды. Стык проверяется сравнением
последнего кадра с первым.
