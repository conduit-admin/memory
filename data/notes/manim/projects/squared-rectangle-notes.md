# Разрезание на квадраты — полные заметки

Хендофф для будущих агентов: вся математика, раскадровка по битам, параметры,
грабли и план недоделанной сцены. Карточка — `squared-rectangle.md`, стиль серии —
`../styles/vertikal.md`.

## Математика

**Критерий.** Прямоугольник $a \times b$ режется на конечное число квадратов
$\iff a/b \in \mathbb{Q}$.

- **Тривиальная сторона** ($a/b\in\mathbb{Q}\Rightarrow$ можно). $a/b = m/n$ с
  целыми $m,n$ $\Rightarrow$ общая мера $s = a/m = b/n$ $\Rightarrow$ сетка $m\times n$
  равных квадратов со стороной $s$. Это `PlateMorph`.
- **Содержательная** (можно $\Rightarrow a/b\in\mathbb{Q}$) — электрический метод
  Брукса–Смита–Стоуна–Тэтта. Ещё не закодирован (см. «Сцена 4»). Опирается на лемму
  об осепараллельности квадратов (`TiltedContradiction`).

## Концепция серии

- Всё происходит на **листе платины** — процедурная металлическая текстура (numpy
  RGBA $\to$ `ImageMobject`), которую режут / морфят / собирают.
- **В кадре нет русского текста.** Только формулы (`MathTex`); всё словесное — озвучка
  диктора за кадром. Это жёсткое требование владельца для @MathDzeta.
- **Свет закреплён в пространстве** (не привязан к кускам). При разлёте квадратов блик
  стоит на месте, а металл «течёт» под ним — физика статичного источника.

## Архитектура файла

Общая «машинерия» листа вынесена на **уровень модуля**, чтобы сцены стыковались
кадр-в-кадр (сцены 2 и 3 стартуют ровно тем листом, каким кончилась предыдущая):

- Цвета: `PLATINUM = [198,201,209]`, `SPEC_WHITE = [252,252,255]`.
- Геометрия: `MW,MH = 21,34`; `PLATE_H = 9.4`; `PLATE_W = PLATE_H·MW/MH`; `UNIT_W`;
  `PXU = 100` (пикс/юнит текстуры); `HL_REST = 0.38` (положение блика в покое).
- `SQUARES` — спираль Фибоначчи: 8 квадратов сторон 21,13,8,5,3,2,1,1 (площади $=714=21\cdot34$).
- `P(mx,my)` — мат.координаты (y вниз) $\to$ мировая точка; `sq_center`.
- `lighting_L(X,Y,highlight)` — поле света в МИРОВЫХ координатах: $L = 0.70 - 0.42 d
  + 0.50\exp(-(d-h)^2/(2\cdot0.05^2))$, где $d = 0.5(X/\text{PW} - Y/\text{PH} + 1)$.
  Диагональ (тёмная сторона) + один гауссов блик.
- `metal_patch(cx,cy,sx,sy,highlight,reveal,res)` — RGBA-кусок металла по его мировому
  положению. `res=(nx,ny)` фиксирует форму массива (нужно, когда габариты меняются
  покадрово — см. грабли).
- `plate_image(highlight,reveal)` — цельный лист.

Классы: `PlateQuestion`, `PlateMorph`, `TiltedContradiction`. Файл = ролик, класс = сцена.

## Сцена 1 — `PlateQuestion`

Постановка: показываем, что лист можно разрезать на квадраты (нетривиально).

1. **Появление.** `hl: ValueTracker(-0.15)→0.38`, `rev: 0→1`, `ease_out_cubic`, ~1.0 c.
   Лист проявляется из темноты, блик вплывает и замирает. `always_redraw` на `plate_image`.
2. **Разрезы растут из точки.** `seed = P(5.5,9)` — «глаз» спирали. Для каждого квадрата
   берём его ВНУТРЕННИЕ рёбра (не кромку листа). Единый радиус `cutR`: растёт — режем
   от seed наружу; убывает — разрезы **зарастают к центру**. `build_cuts` через
   `always_redraw`: каждое ребро — `Line`, растёт от ближнего к seed конца
   (`Line(near, near + frac·(far-near))`, дёшево). Разрезы едут вместе с квадратами
   (сдвиг ребра на `home·(f-1)`).
3. **Разлёт / сборка.** `spread: ValueTracker`, `SPREAD = 1.18`. Куски — `always_redraw`
   на `metal_patch(текущий центр)`. Свет фиксирован $\Rightarrow$ блик дробится по кускам
   на месте. `BLEED = 0.01` — микроприпуск по внутренним стыкам против шва при `spread=0`
   (по кромке листа НЕ припускать, иначе лист «прыгает» при замене на статичный).
4. **Заживление.** `cutR` убывает $\to$ разрезы затягиваются $\to$ цельный лист.

Тяжёлую пересборку `ImageMobject` делаем ТОЛЬКО на разлёте/сборке; на разрезании и
заживлении под линиями стоит статичный лист.

## Сцена 2 — `PlateMorph`

Тривиальная сторона. `R_TARGET = 0.75` ($a/b=3/4$), `GRID_COLS,GRID_ROWS = 3,4`,
`RES = (640,640)`.

1. **Морф.** Габариты плывут при **сохранении площади**: `ratio: ValueTracker`,
   `w = sqrt(AREA·r)`, `h = sqrt(AREA/r)`. «Дышит» (1.15, 0.55) и оседает на 0.75.
   Свет фиксирован (`lighting_L` на ИСХОДНЫХ габаритах) $\Rightarrow$ блик стоит.
2. **Формула.** `?` (PURPLE, y=6.7) уходит вверх (`FadeOut`, НЕ морф — морф `?`$\to$формула
   владелец отверг как нелогичный) $\to$ скобки-`Brace` сторон `a` (верх), `b` (право)
   $\to$ `a/b = q, q∈ℚ` $\to$ раскрытие `a/b = m/n, m,n∈ℕ` (буква `m`, не `p` — рус.
   традиция; вот откуда числа делений).
3. **Сетка + счётчики.** Сетка $3\times4$ равных квадратов; скобки-**счётчики** `m`
   (снизу, число квадратов по ширине), `n` (слева, по высоте) растут вместе с сеткой.
   Подсветка одной ячейки (обводка ORANGE = цвет `s`, НЕ жёлтая — жёлтый близок к
   золотому `m`), общая мера `s = a/m = b/n`.
4. **Конец.** Подписи каскадом (`LaggedStart` + `FadeOut`), сетка зарастает
   (`scale(0.001)` к центру — для отдельных ЛИНИЙ это ок).

Цвета: `a`—TEAL, `b`—PINK, `m`—GOLD, `n`—BLUE, `q`—PURPLE, `s`—ORANGE.

## Сцена 3 — `TiltedContradiction`

Лемма: все квадраты обязаны быть параллельны сторонам прямоугольника. Стартует листом
3/4 (`W=sqrt(AREA·0.75)`, `H=sqrt(AREA/0.75)`). `THETA = 25°`, `SEED = 13`.

От противного:

1. Наклонный квадрат в средней части + пометка угла `θ` (эталон). Пометка =
   белый **полупрозрачный горизонтальный пунктир** (`DashedLine`, opacity 0.5) +
   жёлтая дуга `Arc(0→THETA)` + подпись `θ`.
2. **Цепочка** квадратов, каждый делит сторону соседа, в одну сторону. Размеры СЛУЧАЙНЫ
   и сильно разные (`uniform(0.4,1.7)`), дрейф вдоль общей стороны
   `uniform(-0.5,0.5)·min(w,w')`; наклон у всех ОДИН — это суть. `SEED=13` подобран,
   чтобы не было режущих глаз мелких ступенек. На каждом новом квадрате метка `θ`
   **перепрыгивает** (появляется на новом, `FadeOut` предыдущего) — «наклон вынужден».
3. Последний квадрат **вылезает за край**. Разрезы цвета фона (`BLACK`): на металле
   читаются как рез, вне листа сливаются с фоном. Вырезанная часть **листа**
   (квадрат $\cap$ лист, клип Сазерленда–Ходжмена) подсвечивается красным «бликом».
4. **Красный блик** — тот же градиент, что белый ($\exp$, $\sigma=0.05$, по той же
   диагонали `d` листа), процедурная RGBA-картинка клипуется по зоне (зона выпуклая —
   тест полуплоскостями), бежит **ВНИЗ** (растущее `d` = вниз-вправо) один раз и
   исчезает — просто указатель на квадрат, заливкой не остаётся.
5. Знак противоречия `!?` (RED, рус. традиция; НЕ `⇒⇐`, НЕ молния — молния спутается
   с эл. методом).
6. **Конец — заживление через `Uncreate`** (контур затягивается на месте). НЕ `scale→0`:
   для замкнутого квадрата стягивание к центру выглядит как сжатие/движение, а не
   заживление.

## Сцена 4 — электрический метод (план владельца, НЕ закодирован)

Замысел (пересказ владельца, физика проверена — верна, это в точности BSST):

- Взять нетривиальный (лучше **совершенный**) квадрированный прямоугольник.
- **Сверхпроводящим гелем** обмазать верх, низ и ВСЕ горизонтальные разрезы $\Rightarrow$
  каждая горизонталь эквипотенциальна = **узел**. **Изоляционным гелем** — ВСЕ
  вертикальные разрезы $\Rightarrow$ ток не пересекает вертикали $\Rightarrow$ в квадрате
  ток строго сверху вниз.
- Контакты «+»/«−» сверху/снизу. Диктор: ток течёт, плотность равномерна, между двумя
  точками одной горизонтали нет разности потенциалов. Гель ничего не меняет физически
  (в однородной пластине с контактами по всей кромке горизонтали и так эквипотенциальны,
  а через вертикали ток и так не течёт) — он лишь даёт читать пластину как цепь.
- **КЛЮЧ (сердце метода, обязателен в озвучке):** каждый квадрат — ОДИН И ТОТ ЖЕ
  резистор. $R = \rho\,(h/w)/t$; у квадрата $h=w$, значит $R$ **не зависит от размера**
  (поверхностное сопротивление). Вот почему задача именно про квадраты.
- **Итог сцены:** узлы цепи = горизонтальные участки геля, квадраты = равные резисторы
  между узлами.
- **Финал** (отдельным битом): решаем Кирхгофа. Единичные сопротивления $\Rightarrow$
  рациональная линейная система $\Rightarrow$ все токи/потенциалы рациональны; потенциал
  узла = высота, ток через квадрат = его сторона; полное сопротивление
  $= \text{высота}/\text{ширина} = R_{\text{экв}} \in\mathbb{Q} \Rightarrow a/b\in\mathbb{Q}$.

Открытые решения:

- **Какое разбиение.** Фибоначчи 21×34 — узлы на y=8..10 тесные из-за крохотных
  квадратов, гель там не разглядеть. Совершенный Морона 32×33 (9 квадратов, ~6
  разнесённых уровней) — эталонный пример BSST, цепь читается красиво.
- **Цвета гелей.** Сверхпроводник — голубой/электрик со свечением; изолятор — янтарь
  или тускло-серый. Контраст «горизонтали ↔ вертикали» мгновенный.
- **Контакты, показ тока** (бегущие вниз точки, гуще в широком квадрате), переход к
  абстрактной схеме (узлы-точки, значки резисторов) — в этой сцене или следующей.

## Техники и грабли

- **Металл** — процедурная numpy-RGBA-текстура, НЕ векторные фигуры. Свет = функция
  МИРОВЫХ координат $\Rightarrow$ физически корректно закреплён в пространстве.
- **Производительность.** Пересобирать `ImageMobject` каждый кадр — ТОЛЬКО на движении.
  На статике — заранее собранный лист + дешёвые `VMobject`-линии. `PXU` низкий: металл
  гладкий, высокое разрешение не нужно.
- **`ImageMobject.become()` требует ОДИНАКОВОЙ формы массива.** `always_redraw` обновляет
  через `become`. Если габариты меняются покадрово (`PlateMorph`) — форма массива
  фиксируется (`RES`), мировой размер через `stretch_to_fit_width/height`. Иначе рендер
  **ВИСНЕТ**: `AssertionError` внутри цикла обновления не выходит наружу, легко принять
  за медленность (полчаса до диагноза).
- **Заживление — `Uncreate`, а не `scale→0`.** Для замкнутого контура стягивание к центру
  = сжатие; для отдельных линий (сетка) `scale(0.001)` к центру ок.
- **Разрезы цвета фона** (`BLACK`) — читаются как рез на металле, невидимы на фоне.
- **Клип** «вырезанной части» и полос блика — Сазерленд–Ходжмен (полигон по
  прямоугольнику / по полуплоскости).
- **Морф `?`→формула отвергнут** владельцем как нелогичный — знак вопроса просто уходит.
- Дробь через `\frac` — ок, когда куски не разъезжаются; иначе собирать вручную из `Line`.
