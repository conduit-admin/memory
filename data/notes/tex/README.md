# LaTeX

## Что где

- `documents/` — **чистовики**: исходник, файл рисунков и собранный PDF рядом.
  Это архив: работа обязана компилироваться сама по себе и не ломаться от правки
  общего файла, поэтому преамбула у готовых работ лежит внутри файла.
  - `documents/zachet/` — ответы на вопросы зачёта, документ на подтему.
    Устройство и замечания о стиле — в README рядом с работами.
- `drafts/` — **черновые версии**, вытесненные чистовиком. Лежат здесь, чтобы
  было видно, что менялось, и не мешались среди готового. Их PDF не хранятся.
- `preamble.tex` — та же преамбула, вынесенная отдельно **для новых документов**.
  Извлечена из готовых, не придумана.
- `notes/` — планы документов: обозначения, формат, структура, что отложено.
  Черновики содержания здесь не держатся: их вытесняет собранный PDF.
- `reference/` — готовые работы, исходников которых нет.
- `styles/` — стили, файл на стиль. Пока один — «Хедлайн»: преамбула, палитра,
  заголовки блоков, рисунки, набор формул

## Порядок работы

1. План в `notes/<тема>-plan.md`: обозначения, формат, структура по параграфам
   и отдельно — что отложено.
2. Черновик в markdown: материал набирается быстро, формулы в `$$...$$`.
3. Перенос в `.tex` с дом-макросами: `**Опр.**` → `\Def`, `$$...$$` → `\[...\]`.
4. Чистовик — **отдельным файлом, а не правкой на месте**. Когда он готов,
   черновик уезжает в `drafts/`, а чистовик занимает обычное имя в `documents/`.
   Общая преамбула на этом шаге вклеивается в файл: в архиве работа
   самодостаточна. Так в готовых работах нет суффиксов вроде `_final`,
   а история версий видна.

Рисунки каждого документа — в файле `<имя>_figs.tex`, каждая картинка отдельной
командой `\newcommand{\figX}{...}`.

Компиляция — всегда с флагом `-cd`:

```
latexmk -pdf -cd tex/documents/zachet/matchings.tex
```

`\input` ищется относительно текущего каталога, а не файла документа, поэтому без
`-cd` из корня репозитория не находится даже `<имя>_figs.tex`. Флаг переводит
latexmk в каталог документа на время сборки.

PDF готовых работ лежат в git намеренно: это то, что читаешь, и оно должно быть
под рукой с телефона — GitHub открывает их прямо в браузере.
