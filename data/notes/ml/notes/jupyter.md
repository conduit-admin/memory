# Jupyter

## Зачем это нужно

Домашки сдаются файлом — CSV с ответом или `.py` с функцией, — а писать их
удобно по кусочку: данные прочитаны один раз, промежуточный результат виден
сразу. Ноутбук даёт ровно это, но у него своя модель исполнения, и на ней
легко ошибиться незаметно.

## Основное

### Запуск

- Нужен Python, в котором стоят jupyter, numpy и pandas. На ПК это venv
  проекта DataAnalysis. Голый `python` не годится: на ПК он открывает
  Microsoft Store, а в системном Python библиотек нет.
- Папка с домашкой в Проводнике → в адресной строке `powershell` → Enter.
  Или правый клик по пустому месту → «Открыть в Терминале».
- Команда, браузер откроется сам:

  ```
  & "$env:USERPROFILE\PycharmProjects\DataAnalysis\.venv\Scripts\python.exe" -m jupyter lab
  ```

  `-m jupyter` — запустить модуль именно из этого venv. Папка, откуда
  запущено, — корень: её файлы видны слева, туда же ложатся ноутбуки.
  Из другой папки — дописать `--notebook-dir=<папка>`.
- Остановить — двойной Ctrl+C в окне PowerShell. Закрытая вкладка браузера
  сервер не останавливает, закрытое окно PowerShell — останавливает.
- Второй запущенный Jupyter молча займёт порт 8889 — порт виден в адресной строке.
- Пакет из ноутбука — `%pip install пакет`: ставит в окружение ядра.
  `!pip` может попасть в чужой pip.

### Ядро

- За ноутбуком стоит отдельный процесс Python — ядро. Все переменные живут
  в нём, а не на странице.
- `[n]` слева от ячейки — номер запуска, `[*]` — считается. Важен порядок
  запуска, а не порядок на странице.
- Перед финальной записью — Kernel → Restart Kernel and Run All Cells.
  Отработал сверху донизу без ошибок — результату можно верить.
- Последнее выражение ячейки выводится само, `;` в конце глушит вывод.

| Клавиши | Действие |
|---|---|
| Shift+Enter | выполнить и перейти дальше |
| Esc, потом A / B | ячейка выше / ниже |
| Esc, потом D D | удалить ячейку, Z — вернуть |
| Esc, потом M / Y | Markdown / Code |
| Esc, потом I I | прервать вычисление |
| Esc, потом 0 0 | перезапустить ядро |
| Tab / Shift+Tab | дополнение / сигнатура |

- `объект?` — документация, `??` — исходник. Сигнатуру проверять так,
  а не по памяти.
- `%pwd` — рабочая папка ядра, относительные пути считаются от неё.
  `%whos` — переменные в ядре, `%timeit` — время выражения.

### Сдать `.py` из ноутбука

- `%%writefile имя.py` первой строкой ячейки записывает её текст в файл.
  Код при этом **не выполняется**.
- Проверять сам файл: `from имя import функция`, вызывать по имени из
  условия, прогнать примеры. Опечатка в имени функции или забытый `return`
  всплывут здесь, а не в Контесте.
- После правки файла — перезапуск ядра: повторный `import` берёт модуль
  из кэша, и работает старая версия.
- Проверки и `print` в файл не класть: код верхнего уровня условия запрещают.

### Ловушки

- Ячейка, меняющая данные на месте, запущенная дважды, применится дважды.
- Затёртое встроенное имя (`sum = ...`) недоступно до перезапуска ядра.
- `.ipynb` — JSON вместе с выводами: большой вывод раздувает файл.
