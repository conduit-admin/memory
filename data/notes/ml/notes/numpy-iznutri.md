# NumPy изнутри

## Зачем это нужно

Без циклов numpy считает в десятки раз быстрее: обрезка 3 млн чисел — 7 мс
против 600 мс циклом на Python. Поэтому решение с циклами в домашках
упирается в 50 баллов из 100. Писать без циклов и не ошибаться можно, только
понимая, что numpy делает с формами массивов.

## Основное

### Массив

- Массив — это буфер с числами подряд, `dtype` (как читать байты), `shape`
  и `strides` (на сколько байт шагнуть по каждой оси). Элемент $(i, j)$
  лежит на $i s_0 + j s_1$ байт дальше начала буфера.
- Подряд в памяти лежит последняя ось: у матрицы $2000\times2000$
  из `float64` `strides == (16000, 8)`.

### Ufunc: поэлементные функции

- `+ - * /`, `np.maximum`, `np.minimum`, `np.sqrt`, `np.floor` — цикл на C
  по всем элементам и **новый** массив. Исходный не меняется.
- Названия — по тому, что функция возвращает: `np.minimum(x, b)` обрезает
  **сверху**, `np.maximum(x, b)` — **снизу**. Обе сразу — `np.clip`.
- Часть операций есть и методом, и функцией: `sum`, `reshape`, `max`, `mean`.
  Часть — только функцией: `np.sqrt`, `np.exp`, `np.log`. `shape` —
  атрибут, без скобок.
- `out=` пишет результат в готовый массив. Входной туда отдавать нельзя.
- `np.floor` даёт `float`, целые — потом `.astype(int)`. Сам `astype(int)`
  отбрасывает дробную часть, это не floor: $-1.5 \to -1$.
- `round` и `np.round` округляют половину к чётному: `round(2.5) == 2`.
  Формулу $\lfloor x\cdot1000+0.5\rfloor$ считать только через floor.

### Broadcasting

- Формы выравниваются **по правому краю**. Недостающая ось — длина 1.
  Ось длины 1 растягивается до соседа. Иначе ошибка.
- Растяжение без копии: шаг 0 байт по растянутой оси.
  `np.broadcast_to(v, (n, m)).strides == (0, 8)`.
- `(n, m)` и `(m,)` — вектор по столбцам. По строкам — форма `(n, 1)`,
  `v[:, None]`.
- Тихая ошибка: у квадратной матрицы вектор длины $n$ приложится
  к столбцам, даже если задуман для строк. Форма это не выдаст.
- Все пары строк: формы `(n, 1, d)` и `(1, n, d)` дают разность
  `(n, n, d)`. Каждый такой массив — $8n^2d$ байт.

### Ufunc изнутри: `np.divide`

Порядок у всех поэлементных функций один:

1. Форма результата — broadcasting **всех** входов, маски `where` тоже.
   Не обязательно форма одного из них: `(2, 1)` и `(1, 3)` дают `(2, 3)`.
2. Тип — по готовым циклам на C, `np.divide.types`: `ff->f`, `dd->d`…,
   целых среди них нет. Поэтому `int / int` даёт `float64`,
   а `float32 / float32` — `float32`. Цикл выбирается **по входам**:
   деление `float32` в `out` типа `float64` даёт `0.3333333432674408` —
   точность потеряна до записи. Нужна точность — приводить вход
   к `float64` до счёта.
3. Запись в `out` по правилу `casting='same_kind'`: `float64 → int64`
   нельзя, `UFuncTypeError`; `float64 → float32` можно — молча, с потерей
   точности.
4. Без `out` результат ложится в новый массив **без очистки памяти**,
   как `np.empty`.
5. Цикл по всем индексам формы результата, адреса — через strides,
   растянутый вход читается с шагом 0. Деление — по IEEE 754:
   $x/0 = \pm\infty$, $0/0 = \text{nan}$. Процессор поднимает флаг,
   numpy после цикла выдаёт `RuntimeWarning`; настраивается `np.errstate`.
6. Возвращается сам `out`: после `r = np.divide(..., out=o)` верно `r is o`.

Ловушки:

- Сигнатура `np.divide(x1, x2, /, out=None, *, where=True, ...)`: третий
  позиционный — `out`. Маска третьим аргументом уедет в `out`: «Cannot cast
  ufunc 'divide' output from float64 to bool». `where` — только по имени.
- `where` — где **считать**. Где `False`, остаётся содержимое `out`,
  без `out` — мусор из памяти. Деления там нет — нет и предупреждения.
- `out` не растягивается: растянуть — шаг 0, и $n$ результатов писались бы
  в одну ячейку. Его форма — ровно форма результата, входы растягиваются
  до неё.
- `np.zeros_like(x)` берёт тип `x`, для целого входа `out` целый. Тип —
  `dtype=np.float64`, или `np.zeros(x.shape)`: там `float64` по умолчанию.
- Отрицание маски — `~mask` или `np.logical_not(mask)`. `not mask`
  на массиве падает: «truth value of an array is ambiguous»; на массиве
  из одного элемента молча срабатывает. `~` на целых — побитовое:
  `~1 == -2`.
- `np.where(cond, a, b)` вычисляет `a` и `b` целиком до выбора: деление
  на ноль всё равно случится, с предупреждением, но в ответ не попадёт.

### Оси

- Ось длины 1 добавляют `a[:, None, :]`, `a.reshape(n, 1, d)`,
  `np.expand_dims(a, 1)` — все без копирования.
- `reshape` — не транспонирование: он раскладывает числа подряд по новой
  форме. `.T` у трёхмерного массива разворачивает **все** оси.
- Ось $k$ — это индекс $i_k$. `sum(axis=k)`: этот индекс пробегает все
  значения и исчезает, остальные остаются. У матрицы `axis=0` —
  $S_j = \sum_i A_{ij}$, одно число на столбец. Форма результата — `shape`
  без позиции $k$: из `(2, 3, 4)` при `axis=0` — `(3, 4)`. Так же `mean`,
  `std`, `max`, `argmax`. `axis=-1` — последняя ось, `axis=(1, 2)` —
  две сразу, без `axis` — всё в одно число.
- «По строкам» и «по столбцам» понимают в обе стороны. Надёжнее вопрос:
  какой индекс должен исчезнуть. Одно число на признак — исчезают объекты,
  `axis=0`.
- Свёртку обычно возвращают к исходному массиву: `A - A.mean(axis=k)`.
  Свёрнута ось 0 — остаток формы совпадает с правым краем, приклеится сам.
  Любая другая — нужен `keepdims=True`: ось остаётся длины 1 и растягивается.
  Без него `(2, 3)` и `(2,)` дают `ValueError`, а у квадратной матрицы —
  тихо неверный ответ.
- Умолчания разные: у `sort` и `argsort` `axis=-1`, у `sum`, `max`, `argmax` —
  весь массив. `argmax` без оси вернёт индекс в вытянутом массиве.
  `axis` писать явно.
- Проверять на формах с разными длинами, вроде `(2, 3, 4)`: при равных
  длинах не та ось даёт верную форму и неверные числа.

### Сортировка

- `np.sort` возвращает отсортированную копию. `a.sort()` — на месте
  и возвращает `None`.
- `np.argsort` — индексы: на месте $p$ стоит элемент `idx[p]`. Это не места
  элементов: для `[30, 10, 20]` `argsort` даёт `[1, 2, 0]`, а места —
  `[2, 0, 1]`, то есть `argsort` от `argsort`.
- По строкам матрицы — `axis=1`. Значения по индексам —
  `np.take_along_axis(a, idx, axis=1)`.
- По умолчанию сортировка **неустойчива**: равные идут в произвольном
  порядке. На ПК — уже с 10 элементов при повторах, а на маленьком примере
  может совпасть случайно. `kind="stable"` — равные по возрастанию индекса.
  `stable=True` есть только с numpy 2.0, `descending=True` — с 2.5; версия
  в Контесте неизвестна, поэтому `kind="stable"`.
- По убыванию с сохранением порядка равных — `argsort(-a, kind="stable")`.
  `[::-1]` переворачивает и равные.
- `np.argpartition` выбирает $k$ наименьших за $O(n)$, но порядок внутри
  частей не определён, и на границе равных — тоже.
- `np.lexsort((второй, главный))` — главный ключ стоит **последним**.

### Диагональ, срезы

- `np.fill_diagonal(D, v)` меняет `D` на месте и возвращает `None`:
  `D = np.fill_diagonal(...)` теряет матрицу. Внутри — запись в каждый
  $(n+1)$-й элемент плоского буфера. `np.inf` пишется только во float-массив.
- Исключить саму точку в задаче на соседей — `inf` на диагональ, а не срез
  с первого столбца: совпадающая точка с меньшим индексом встанет раньше
  самой точки.
- `a[:, 0:k]` — все строки, столбцы $0..k-1$: правый конец не входит.
  Срез — окно в массив, не копия.

### Типы и точность

- `float64`: $\varepsilon \approx 1.1\cdot10^{-16}$. Сумма $d$ неотрицательных
  слагаемых ошибается не больше чем на $d\varepsilon$.
- `float32`: $\varepsilon \approx 6\cdot10^{-8}$ — уже порядок допуска $10^{-7}$.
- `int32` вмещает $\approx 2.1\cdot10^9$. Квадрат разности порядка $2\cdot10^6$
  переполняет его молча: числа оборачиваются, сумма уходит в минус, корень
  даёт `nan`.
- `nan` в целые: numpy молча даёт $-9223372036854775808$, pandas падает.
- `np.maximum(nan, 1.0)` — `nan`; `np.fmax` пропуск игнорирует.
- Деление на 0 в массиве не падает: $x/0$ даёт `inf`, $0/0$ даёт `nan`.
- std постоянного столбца не обязательно 0. Среднее округляется:
  $\hat\mu = v(1+\delta)$, $|\delta|$ — несколько $\varepsilon$, отсюда
  $\hat\sigma = |v\delta| \sim \varepsilon|v|$ — ошибка относительная. Замер
  на длинах от 3 до $10^6$: либо ровно 0, либо от $\varepsilon|v|$
  до $4\varepsilon|v|$. У `[0.1, 0.1, 0.1]` среднее `0.10000000000000002`,
  std `1.4e-17`, и $(x-\hat\mu)/\hat\sigma$ даёт `[-1, -1, -1]` вместо нулей.
- Проверить «почти ноль»:
  - `np.isclose(s, 0)` — это `s <= 1e-8`: в формуле
    $|a-b| \le \text{atol} + \text{rtol}\,|b|$
    при $b = 0$ остаётся `atol`. Порог абсолютный, ошибка
    относительная: постоянный столбец около $10^{10}$ даёт std `1.9e-6`
    и не ловится, живой `[1e-10, 2e-10, 3e-10]` со std `8.2e-11`
    обнуляется.
  - Относительный порог $\hat\sigma_j \le C\varepsilon\max_i |x_{ij}|$:
    $C$ — на глаз, десятки; $\varepsilon$ — того типа, в котором счёт.
    `np.finfo(np.float64).eps` — это $2\varepsilon$, $2.2\cdot10^{-16}$.
  - Без порога: $\sigma_j = 0 \iff$ все значения равны, то есть
    max = min. Сравнение без арифметики, округлению негде взяться.
    Метода `.ptp()` в NumPy 2 нет, функция `np.ptp` есть. Обратная дыра —
    исчезновение порядка: у `[1e-200, 2e-200]` квадраты отклонений
    $\approx 10^{-401}$ меньше наименьшего `float64` и становятся нулём,
    std ровно 0 при max ≠ min.
- `ddof` по умолчанию: у `np.std` — 0, у `.std()` в pandas — 1.
